# 04 Wan 1.3B 相关实验：输入级渲染、2D 轨迹头与 A14B Oracle

> 日期：2026-11-06
> 范围：本文只整理“Wan 1.3B”相关的三类实验，并明确它们与 7-DOF 动作空间的关系。所有数字均来自对应实验报告与评测脚本；未测量的量会标注为“未记录”或“约”。
> 总览见 [`00_overview.md`](00_overview.md)。

## 摘要（总）

- 先区分三件事：**(a)** `Wan2.1-Fun-V1.1-1.3B-Control` + Control LoRA，是**输入级渲染器**；**(b)** `PF_Wan 1.3B`，是 `Wan2.1-T2V-1.3B` + **2D 轨迹低层头**；**(c)** `PF_Wan A14B` oracle，是**另一个模型规模**的 2D 轨迹 + latent 修正实验，不是 1.3B。
- (a) 的链路是 `q(t) → PyBullet 语义 control 视频 → Wan 1.3B + LoRA → RGB`。CNF 只在外部关节空间生成 `q(t)`，Wan 内部没有硬投影。
- (a) 的干净数据结果：LoRA 把 waypoint EPE 从 `8.87` 降到 `6.56 px`，PSNR 从 `31.06` 升到 `34.98 dB`；velocity-only 相对 waypoint-only 在 4/4 样本上更好，但幅度只有约 `0.2 px / 0.16 dB`。
- (a) 的含噪数据结果：可靠速度（oracle）在 8/8 样本上改善关节 RMSE；从含噪 action 直接差分估计的速度反而更差。结论是**速度估计器是瓶颈**，不是 CNF 投影。
- (b) 的 100 步 held-out：低层目标 `0.00259`（CNF）vs `0.01104`（soft），diffusion loss `0.26613` vs `0.26542`；但生成视频没有明显提升，动态位移只有 `3.44` vs `2.32 px`，参考为 `80.89 px`。这是**负结果/不确定结论**，不是对 CNF 想法的反证。
- (c) 的 A14B oracle：CNF 与 soft 的动态 EPE 都约 `49 px`，CNF 没有实质优势，前后向一致性反而更差。冻结 VAE + 只修正 latent 的映射是主要瓶颈。
- 当前**没有**“Wan 1.3B + 7-DOF latent-level”实验：1.3B 只做了输入级 2D control 渲染；7-DOF latent-level 只在 release 的小型 3D U-Net 上验证。原因和边界见 §5。

## 1. 三类对象先分清

| 代号 | 模型 | 动作/约束接口 | 是否 7-DOF | 约束发生在哪里 | 能证明什么 |
|---|---|---|---|---|---|
| **A** | `Wan2.1-Fun-V1.1-1.3B-Control` + Control LoRA | skeleton/语义 control 视频 → RGB 视频 | **否** | 外部 `q(t)` 关节空间；Wan 只渲染 | 1.3B 控制渲染器能否跟随 CNF 生成的 control；LoRA 是否必要；velocity 是否改善像素指标 |
| **B** | `PF_Wan 1.3B`：`Wan2.1-T2V-1.3B` + low-level trajectory head | 2D tracks `[B,K,T,2]` | **否** | low-level head 的 2D 轨迹目标 + CNF 对齐损失 | 硬约束能否降低低层目标并泛化到 held-out clip；能否转化为视频质量 |
| **C** | `PF_Wan A14B`：官方 `Wan2.2-A14B-I2V` | 2D CoTracker tracks + VAE latent correction | **否** | 推理时冻结模型，只优化 latent 修正 | 精确 CNF 投影是否优于 soft guidance；latent-only 修正是否足够 |

关键区别：

- A 和 B 都是“1.3B 量级”，但不是同一个 backbone：A 是 **Fun-Control**（控制视频条件），B 是 **T2V**（文本到视频，使用固定干净 first latent 作为图像条件代理）。
- C 不是 1.3B，而是 A14B；它经常和 B 一起被讨论，因为二者都使用 PF_Wan 的 2D 轨迹接口。
- 三者都**不是** 7-DOF 关节 latent 模型。A 的 latent 是视频 VAE latent；B/C 的低层目标是 2D 轨迹；7-DOF 关节空间只出现在 A 外部的 CNF 运动层，以及 release 的小型 7 关节 action WM 中。
- 同一个 1.3B Control LoRA 接口也用于 6-DOF pick-and-place 的像素评测（见 `report_pickplace.md`）；但本文所有数字均来自**双摆**实验，不要把 6-DOF 的 EPE/PSNR 与本文表格混用。

## 2. 输入级路径 A：1.3B Control + LoRA

### 2.1 链路

```text
稀疏 waypoint / 速度约束
        │
        ▼
CNF 硬投影（关节空间，7 关节 × 10 阶 Legendre = 70 维）
        │
        ▼
q(t)（17 帧）
        │
        ▼
PyBullet 渲染语义 control 视频（skeleton）
        │
        ▼
Wan2.1-Fun-V1.1-1.3B-Control + Control LoRA
        │
        ▼
RGB 视频（256×256，17 帧）
```

这条路径中，CNF 的“硬约束”只在 `q(t)` 上成立；Wan 看到的只是 control 视频，像素空间没有硬保证。这是后文所有“像素收益小”的前提。

### 2.2 数据与 control

| 项目 | 设置 |

| 分辨率 / 帧数 | 256×256，17 帧 |
| Control | skeleton video：蓝/橙连杆 + 白色关节 |
| 干净 held-out | 4 个样本，首帧来自 GT target video |
| 含噪 held-out | 8 个样本，目标视频始终是干净 GT |
| 运动表示 | 7 关节 × 10 阶归一化 Legendre 基，70 维系数 |

### 2.5 评测指标与一个重要偏差

| 指标 | 定义 |
|---|---|
| **waypoint EPE** | 第 0/8/16 帧橙色连杆末端到 GT 末端的像素距离 |
| **track EPE** | 所有帧检测末端到 GT target 检测末端的平均像素距离 |
| **PSNR** | 生成视频 vs GT target |
| **endpoint jerk** | 检测末端轨迹的三阶差分均值 |

注意：256 分辨率下，skeleton 的白色关节圆半径为 12 px，会覆盖连杆末端，导致**即使 GT control 也有约 `6.5 px` 的 waypoint EPE 系统偏差**。因此 waypoint EPE 只适合同条件相对比较，绝对值不代表真实跟踪误差。

### 2.6 Base vs LoRA（同一 GT control）

| 样本 | Base waypoint EPE | Base PSNR | LoRA (gt) waypoint EPE | LoRA (gt) PSNR |
|---|---:|---:|---:|---:|
| 0 | 10.46 | 30.50 | 7.45 | 34.58 |
| 1 | 5.85 | 33.52 | 6.11 | 36.13 |
| 2 | 7.12 | 31.81 | 6.60 | 34.27 |
| 3 | 12.06 | 28.42 | 6.11 | 34.92 |
| **均值** | **8.87** | **31.06** | **6.56** | **34.98** |

结论：

> 1.3B Control base 已经能跟随 skeleton（不同于 5B 零样本）；LoRA 仍有稳定提升：EPE `8.87 → 6.56 px`，PSNR `31.06 → 34.98 dB`。

### 2.7 CNF 控制对比（均用 LoRA）

| Control | waypoint EPE | track EPE | PSNR | endpoint jerk |
|---|---:|---:|---:|---:|
| waypoint only | 6.65 | 3.41 | 34.16 | 9.56 |
| **velocity only** | **6.42** | **3.22** | **34.31** | **9.20** |
| ground truth | 6.56 | 2.35 | 34.98 | 10.69 |

Paired delta（velocity − waypoint，4 个样本）：

| 指标 | 每样本差值 | 均值 ± SE | 方向 |
|---|---|---:|---|
| waypoint EPE | −0.04, −0.32, −0.43, −0.11 | **−0.22 ± 0.09 px** | 4/4 velocity 更好 |
| track EPE | −0.06, −0.00, −0.37, −0.35 | **−0.20 ± 0.10 px** | 4/4 velocity 更好 |
| PSNR | +0.04, +0.01, +0.27, +0.30 | **+0.16 ± 0.07 dB** | 4/4 velocity 更好 |
| endpoint jerk | −0.14, −1.02, −0.35, +0.05 | −0.36 ± 0.23 | 3/4 velocity 更低 |

结论：

> velocity-only 在 EPE 和 PSNR 上 **4/4 样本一致优于** waypoint-only，但幅度很小（约 `0.2 px / 0.16 dB`）；4 个样本下还不构成统计显著。

### 2.8 轨迹级分析

velocity 约束只加在第 7 帧，但它改变了整条轨迹：

| 样本 | waypoint joint MAE | velocity joint MAE | waypoint RMSE | velocity RMSE |
|---|---:|---:|---:|---:|
| 0 | 0.0189 | **0.0122** | 0.0279 | **0.0159** |
| 1 | 0.0073 | **0.0069** | 0.0122 | **0.0113** |
| 2 | 0.0182 | **0.0158** | 0.0262 | **0.0206** |
| 3 | 0.0401 | **0.0276** | 0.0610 | **0.0371** |

- 关节 RMSE 降低：`43% / 8% / 21% / 39%`；
- waypoint 与 velocity 的控制轨迹本身差异很小（平均 `0.001–0.024 rad`），说明 motion prior 在干净 waypoint 下已经接近自然速度；
- 速度约束的主要作用是**把整条轨迹拉回 GT 动力学**，而不是只修一帧。

### 2.9 与 GT control 的差距

- track EPE：velocity `3.22 px` vs GT `2.35 px`；
- PSNR：velocity `34.31 dB` vs GT `34.98 dB`；
- 差距约 `0.9 px / 0.7 dB`。这比 5B 时的 `0.24 px / 0.01 dB` 更可解释，但仍说明**渲染器是剩余瓶颈**。

### 2.10 endpoint jerk 不能当作自然性指标

GT control 的 endpoint jerk 是 `10.69`，高于 velocity 的 `9.20`。原因是 CNF 投影后的轨迹比 GT 更平滑（轻微过平滑），所以“jerk 更低”不等于“更自然”。后续应报告 jerk 与 GT 的比值，而不是单纯追求更低。

## 3. 含噪 waypoint 实验（8 样本）

### 3.1 目的

干净 waypoint 下，waypoint-only 和 velocity-only 的像素差异很小（`6.65 vs 6.42 px`），因为 motion prior 本身已经接近自然速度。本实验回答：

> **当 waypoint 和 action 都带噪声时，速度硬约束是否仍然有用？**

### 3.2 设置

| 项目 | 设置 |
|---|---|
| 数据 | 8 个 held-out 样本，256×256，17 帧 |
| 模型 | `Wan2.1-Fun-1.3B-Control` + Control LoRA（1500 步） |
| Waypoint 帧 | 第 0/8/16 帧 |
| 第 0 帧 | 保持精确，与首帧一致 |
| 第 8/16 帧 | 加高斯噪声，`σ = 4 px`（256 分辨率） |
| 速度帧 | 第 7 帧（CNF 空间） |
| 速度估计 | 从含噪 action 的第 5/9 帧做中心差分；折算到归一化时间单位（`×15`）；IK 角度做连续分支展开，避免 `±π` 跳变 |
| 目标视频 | 始终是**干净 GT** |

对比方法：

| 方法 | 位置约束 | 速度约束 |
|---|---|---|
| `noisy_waypoint` | 含噪位置 | 无 |
| `noisy_velocity` | 含噪位置 | 含噪 action 估计速度 |
| `noisy_oracle` | 含噪位置 | **GT 速度**（上界，隔离速度估计误差） |

### 3.3 轨迹级结果（先于像素）

关节 RMSE vs 干净 GT：

| 样本 | noisy waypoint | noisy velocity（估计） | noisy oracle velocity |
|---|---:|---:|---:|
| 0 | 0.0697 | 0.0797 | **0.0686** |
| 1 | 0.2045 | 0.3282 | **0.2010** |
| 2 | 0.1151 | 0.1419 | **0.0881** |
| 3 | 0.0917 | 0.1332 | **0.0855** |
| 4 | 0.0566 | 0.0958 | **0.0489** |
| 5 | 0.0639 | **0.0629** | **0.0472** |
| 6 | 0.1103 | **0.0916** | **0.0756** |
| 7 | 0.1253 | 0.2418 | **0.1149** |

均值：

| 方法 | 关节 RMSE | 相对 waypoint |
|---|---:|---:|
| noisy waypoint | 0.1046 | — |
| noisy velocity（估计） | 0.1469 | **+40.5%** |
| noisy oracle velocity | 0.0912 | **−12.8%** |

结论：

1. **oracle 速度在 8/8 样本上都优于 waypoint-only**，说明速度约束本身有效；
2. **从含噪、低频 action 直接差分估计的速度在 6/8 样本上反而更差**，因为速度估计误差被硬约束放大；
3. 速度约束的收益高度依赖速度估计质量。

### 3.4 像素级结果（8 样本 × 3 方法）

| 方法 | clean-anchor EPE | noisy-anchor EPE | track EPE | PSNR | 关节 RMSE |
|---|---:|---:|---:|---:|---:|
| noisy waypoint | 9.62 | 8.99 | 6.45 | 32.55 | 0.105 |
| noisy velocity（估计） | 8.24 | 7.47 | 6.82 | 32.11 | 0.147 |
| noisy oracle velocity | 8.22 | 7.28 | **5.26** | **32.96** | **0.091** |

Paired delta（相对 noisy waypoint）：

| 指标 | oracle velocity | estimated velocity |
|---|---:|---:|
| track EPE | **−1.18 ± 0.64 px**（6/8 更好） | +0.37 ± 1.01 px（2/8 更好） |
| PSNR | **+0.41 ± 0.16 dB**（7/8 更好） | −0.45 ± 0.32 dB（2/8 更好） |
| 关节 RMSE | **−0.013 ± 0.004**（8/8 更好） | +0.042 ± 0.018（2/8 更好） |

逐样本关键点：

- **oracle**：track EPE 在样本 1/2/4/5/6/7 上更好，PSNR 在 7/8 上更好；样本 6 的 track EPE 从 `10.32 → 7.11 px`，样本 5 从 `9.90 → 5.13 px`；
- **estimated**：样本 1 的 track EPE `4.49 → 7.86 px`、PSNR `31.10 → 29.38 dB`，是速度估计误差被硬约束放大的典型；样本 5 是唯一明显更好的样本（waypoint 本身在该样本上控制失败，track `9.90 px`）。

> 注：`report_noisy.md` 的像素表中 estimated 的 `6.82 / 32.11` 被加粗，但同文配对统计为 `+0.37 px / −0.45 dB`、仅 2/8 更好；以配对统计和结论为准。

### 3.5 结论：条件性 claim

```text
可靠速度 → velocity-only > waypoint-only
不可靠速度 → waypoint-only 更稳
```

- `4 px` waypoint 噪声已经会让 waypoint-only 偏离干净 GT；
- 速度约束是**硬约束**，估计误差不会被平均掉，而是被投影到整条轨迹；
- oracle 速度证明“如果速度可靠，约束是正收益”；
- 因此问题不在 CNF 投影，而在**速度估计器**。

### 3.6 两个控制实验

**干净 action 的有限差分**：用无噪声 action 的第 5/9 帧做同样的中心差分，速度估计误差降到 `0.004–0.25`（归一化时间单位），轨迹 RMSE 在 7/8 样本上优于 waypoint-only。例如样本 2 从 `0.1151 → 0.0925`，样本 6 从 `0.1103 → 0.0670`。这说明投影和速度目标的单位/方向都正确，**唯一的问题是 action 噪声**。

**多帧平滑也没有救回来**：用 9 个含噪 action 帧（1,3,5,6,7,8,9,11,13）做局部二次拟合，再取第 7 帧导数；速度误差仍然很大（最大约 `1.5`），轨迹 RMSE 在 6/8 样本上仍差于 waypoint-only；宽窗口拟合会低估速度幅值。结论是**简单的线性平滑不够，需要更可靠的速度估计器或不确定性建模**。

## 4. PF_Wan 1.3B：2D 轨迹低层头（不是 7-DOF）

### 4.1 模型与数据

| 项目 | 设置 |
|---|---|
| Backbone | `Wan2.1-T2V-1.3B`，1.419B 参数 |
| 低层头 | 带 visibility gate 的逐轨迹 Legendre trajectory field |
| 轨迹接口 | **2D tracks** `[B,K,T,2]` |
| 硬件 | 单张 NVIDIA A100-SXM4-40GB |
| 数据 | 4 个 BridgeData V2 示例 clip |
| 训练分辨率 / 帧数 | 256×256，17 帧 |
| 微调方式 | backbone 全参数微调 |
| Feature hook | DiT block 15，hidden width 1536 |
| 对比 baseline | 相同 seed/config 的 soft trajectory MSE |

这个 1.3B T2V backbone 使用固定的干净 first latent 作为图像条件代理；T2V 路径跳过 A14B 专用的 `y` conditioning tensor。因此它**不是**真正的 image-to-video backbone。

### 4.2 2D 头的硬性限制

`PhysisForcing/pf_wan/project/subtools/cnf/trajectory_constraints.py` 的 `cnf_trajectory_alignment` 明确要求：

```text
predicted:  [B, K, T, 2]
target:     [B, K, T, 2]
visibility: [B, K, T]

if dims != 2:
    raise ValueError(f"expected 2D trajectories, got {dims} coordinates")
```

因此该低层头不能直接接收 7 关节向量 `[B,T,7]` 或 70 维 Legendre 系数 `[B,70]`；要做 7-DOF latent-level，必须新增 joint head/action encoder，并重新训练，而不是改一个 loss 参数即可。

### 4.3 20 步冒烟结果

| 20 步平均指标 | CNF | Soft |
|---|---:|---:|
| Diffusion loss | 0.23207 | 0.23303 |
| Low-level trajectory loss | 0.00258 | 0.00840 |
| 最终 diffusion loss | 0.15430 | 0.15590 |
| 最终 low-level loss | 0.00090 | 0.00640 |
| Batch time | 0.868 s | 0.783 s |

CNF 诊断：每步平均 32.5 条轨迹进入硬约束；平均条件数 `2.96`；最大等式残差低于 `2.3e-16`；1.3B backbone 梯度保持有限；单张 40GB A100 未出现 CUDA OOM。

该冒烟测试只使用 4 个训练 clip、20 个 optimizer step，且没有 held-out 视频评估，**不是生成质量结论**。

### 4.4 100 步 held-out 对比

4 个示例被划分为 **3 个训练 clip + 1 个 held-out clip**（`episode_047007`）。CNF 与 soft 从相同初始化开始，使用相同 seed 和数据顺序训练 100 步，并在 held-out clip 上以零学习率评估 10 个时间步。

100 步训练均值：

| 指标 | CNF | Soft |
|---|---:|---:|
| Diffusion loss | 0.18814 | 0.18858 |
| Low-level objective | 0.00113 | 0.00545 |
| 最终 diffusion loss | 0.11100 | 0.11040 |
| 最终 low-level objective | 0.00040 | 0.00360 |

Held-out 匹配时间步均值：

| 指标 | CNF | Soft |
|---|---:|---:|
| Total objective | 0.26873 | 0.27649 |
| Diffusion loss | 0.26613 | 0.26542 |
| Low-level objective | **0.00259** | 0.01104 |

- CNF 的 held-out low-level objective 为 `0.00259`，soft 为 `0.01104`，约低 `4.3` 倍（`0.01104 / 0.00259 ≈ 4.26`）；
- diffusion loss 仅高 `0.27%`（`0.26613 vs 0.26542`）；
- 评估诊断：每个样本有 33 条轨迹通过 hard-constraint gate；平均条件数 `2.93`；最大等式残差低于 `2.3e-16`；无 NaN/Inf 或 OOM。

### 4.5 生成视频评估

两个 100 步 checkpoint 都在 `episode_047007` 上使用相同首帧、prompt、seed 和 sampler 解码；输出 17 帧、256×256、5fps。使用 CoTracker3 跟踪首帧 8×8 网格；参考 clip 中 64 条轨迹里有 17 条最大位移至少 2 px，被视为动态轨迹。

Detailed prompt：

| 指标 | CNF | Soft | Reference |
|---|---:|---:|---:|
| 动态轨迹 EPE 均值 | **66.27 px** | 73.29 px | 目标轨迹 |
| 动态轨迹 EPE 中位数 | **48.32 px** | 55.88 px | 目标轨迹 |
| 全轨迹 EPE 均值 | **8.37 px** | 11.82 px | 目标轨迹 |
| 前后向 EPE 中位数 | **1.02 px** | 1.32 px | 0.27 px |
| 前后向 EPE p95 | 18.80 px | **15.43 px** | 1.15 px |
| 动态轨迹位移 | **3.44 px** | 2.32 px | 80.89 px |

使用原始截断训练 caption 时，两种生成结果几乎完全静止，CNF 与 soft 轨迹平均只相差 `0.34 px`。使用 detailed caption 时，模型会生成很大的胡椒堆并移动部分机械臂，但都没有复现参考扫动轨迹；CNF 动态位移只有参考的约 `4%`（`3.44 / 80.89`），CNF/soft 轨迹平均仍相差 `1.29 px`。视觉对照也显示机器人结构和物体几何发生明显变化。

额外测试了未微调 base checkpoint：它在部分轨迹上移动更多，但几何明显损坏，tracking visibility 也低很多。因此 100 步微调改善了静态外观和时序稳定，但没有改善任务级运动。

### 4.6 结论与失败判据

> 硬约束改善了 low-level 训练目标，但没有产生明显的生成视频提升。这是当前 100 步设置的**初步负结果，不是对 CNF idea 的反证**。

判据：

| 判据 | 观察 | 判定 |
|---|---|---|
| held-out low-level objective 明显低于 soft | `0.00259 vs 0.01104` | 通过 |
| diffusion loss 不严重退化 | `0.26613 vs 0.26542`（+0.27%） | 通过 |
| 动态 EPE 明显低于 soft | `66.27 vs 73.29 px`，但两者都远离参考 | 弱/不足 |
| 动态位移接近参考 | `3.44 / 2.32 px` vs `80.89 px` | 失败（几乎静止） |
| 前后向一致性不退化 | CNF p95 `18.80` vs soft `15.43`，存在长尾 | 未通过 |

限制：只有 1 个 clip、1 个 seed、100 个 optimizer step，且 1.3B T2V 不是真正的 image-to-video backbone。因此结论是**负结果/不确定**，不能据此否定 CNF；下一步应在更多 clip 上训练更久、评估多个 seed，并使用真正的 image-conditioned backbone。

| 采样 | 20 个 Euler 步 |
| Guidance | 5.0 |
| Seed | 0 |
| 采样时间 | 约 11 秒（17 帧） |

官方模型能生成连续的夹爪运动，是有效的原生 I2V 基线，明显优于把 Wan2.1-T2V-1.3B 当作 I2V 使用的实验。8×8 CoTracker 指标：

| 指标 | 官方 PF_Wan | 参考 |
|---|---:|---:|
| 动态轨迹 EPE 均值 | 58.65 px | 目标轨迹 |
| 动态轨迹 EPE 中位数 | 50.84 px | 目标轨迹 |
| 全轨迹 EPE 中位数 | 0.59 px | 目标轨迹 |
| 静态区域 EPE 均值 | 0.86 px | 目标轨迹 |

81 帧长版本：256×256、5fps，采样约 47 秒，未 OOM；匹配采样 17 帧评估得到动态 EPE `58.39 px`、静态 EPE `1.26 px`、动态位移 `52.32 px`，参考动态位移 `80.89 px`。

### 5.2 Oracle 设置

第一个 oracle 实验冻结官方 PF_Wan，并从其生成视频开始：视频被编码到 VAE latent，只优化一个加性 latent correction；参考 CoTracker 轨迹作为答案。

| 项目 | 设置 |
|---|---|
| 目标轨迹 | 参考 clip 的 CoTracker tracks |
| Query grid | 8×8 |
| 动态轨迹 | 16 条 |
| 每条轨迹最多约束帧 | 4 个均匀约束帧 |
| 优化变量 | latent tail 的加性修正；首帧固定 |
| 优化器 | SGD |
| Steps | 50 |
| LR | 1.0 |
| Latent 正则 | 0.01 |
| Image 正则 | 0.05 |
| 每步更新范数 | 0.01 |
| 对比 | Soft MSE vs CNF |

Soft 和 CNF 使用相同的 16 条动态轨迹、query grid、图像/latent 正则项和固定梯度预算。

### 5.3 Oracle 结果

内部优化指标：

| 指标 | Soft | CNF |
|---|---:|---:|
| 初始选定轨迹 EPE | 50.01 px | 50.01 px |
| 最终更新前 EPE | **45.94 px** | 49.53 px |
| CNF 修正场残差 | — | 约 `1e-15` |

独立 8×8 CoTracker 评估：

| 指标 | Roundtrip baseline | Soft | CNF |
|---|---:|---:|---:|
| 动态 EPE 均值 | 54.84 px | **49.04 px** | 49.07 px |
| 动态 EPE 中位数 | 43.34 px | **40.11 px** | 38.72 px |
| 静态 EPE 均值 | 0.94 px | **0.74 px** | 0.89 px |
| 前后向 EPE p95 | **3.63 px** | 62.49 px | 75.12 px |

结论：

- 两种投影都降低了相对 VAE roundtrip baseline 的轨迹误差；
- **CNF 相比 soft 没有实质优势**：动态 EPE `49.07 vs 49.04 px`，基本持平；CNF 动态中位数略好（`38.72 vs 40.11 px`），但静态误差更差（`0.89 vs 0.74 px`），时序一致性明显恶化（p95 `75.12 vs 62.49 px`，baseline `3.63 px`）；
- 视觉上也只有轻微运动变化，两种方法都没有让官方生成遵循参考扫动。

### 5.4 为什么 latent-only 修正是瓶颈

CNF 线性求解只在**构造出的修正场**上精确（残差约 `1e-15`），不代表生成视频具有零轨迹残差。修正仍需通过冻结 VAE 和 latent 优化传递到视频，而该映射是主要瓶颈：

1. 优化变量只是 VAE latent 的加性 tail correction，首帧固定；latent 的局部变化经 VAE 解码后会被平滑、混合，无法精确对应 2D 轨迹；
2. CoTracker 的 2D 轨迹与 VAE latent 之间没有可逆映射；梯度通过冻结 VAE 和 tracker 反传，稀疏轨迹约束容易被解码器“摊平”；
3. 固定梯度预算下，latent correction 的幅度很小，视觉变化轻微；
4. 精确匹配所有 CoTracker 点也可能有害，因为 tracker 坐标本身有噪声。

### 5.5 运动场 Warp 验证

为了测试轨迹约束能否直接影响像素，使用 8×8 CoTracker 控制网格对生成视频执行 warp。控制点轨迹从每条选定轨迹最多 4 个锚点中，通过 soft regression 或 exact CNF solve 插值得到。

| 方法 | 动态 EPE | 视觉问题 |
|---|---:|---|
| Roundtrip baseline | 54.84 px | — |
| RBF + soft | 39.19 px | 严重的流体状拖影 |
| RBF + CNF | 50.06 px | 同上 |
| 固定拓扑三角网格 + soft | 22.60 px | 明显的三角形撕裂和错误局部几何 |
| 固定拓扑三角网格 + CNF | 26.71 px | 同上 |
| 每帧精确参考位移的 dense target warp | 未报告 | 不可接受的视觉伪影 |

结论：

> 主要问题不是 CNF 能否求解轨迹方程，而是如何把稀疏轨迹变化转换为**稠密、遮挡感知且光度一致**的视频变形。简单的 RBF/三角网格插值器被否定；认真实现需要可学习的 dense motion field 和 inpainting/refinement renderer。

## 6. 什么 是 / 不是 7-DOF

### 6.1 定义

| 对象 | 动作/约束空间 | 是否 7-DOF | 说明 |
|---|---|---|---|
| 6-DOF pick-and-place 任务 | 末端 6-DOF 位姿 | 机器人有 7 个臂关节 | 任务是 6-DOF；Franka Panda 是 7 关节冗余臂 |
| `VideoWorldModel6D`（release） | `q [B,17,7]`；`c [B,70]` | **是（7 关节）** | 12.88M 参数 3D U-Net；不是 Wan 1.3B |
| Wan2.1-Fun-1.3B-Control + LoRA | skeleton/语义 control 视频 | **否** | 输入级渲染；CNF 在外部关节空间 |
| PF_Wan 1.3B low-level head | 2D tracks `[B,K,T,2]` | **否** | `dims == 2` 硬性检查；没有 joint head |
| PF_Wan A14B oracle | 2D tracks + VAE latent | **否** | latent-only correction；没有 7-DOF 动作 |

在 release 的实现中，`q` 是 7 个臂关节；夹爪开合由 `GRASP_FRAMES` 单独控制，不进入 `q`。运动 latent 是 `7 关节 × 10 阶 Legendre = 70` 维。这里的“7-DOF”指**7 个关节的显式运动 latent**，不是“7 维末端位姿”。

### 6.2 为什么 1.3B 的 7-DOF latent-level 不能直接得到

1. **PF_Wan low-level head 是 2D 的**：它接收 `[B,K,T,2]`，`cnf_trajectory_alignment` 在 `dims != 2` 时直接报错；没有把 7 关节 `q` 或 70 维系数 `c` 映射到视频的 joint encoder。
2. **Wan2.1-Fun Control 是渲染器**：它只接收 control 视频，内部 latent 是视频 VAE latent，不暴露 7-DOF 动作状态；CNF 的硬约束在模型外部。
3. **PF_Wan 1.3B 使用 T2V backbone**：它用固定干净 first latent 作为图像条件代理，不是真正的 I2V；更没有 7-DOF action head。
4. **要得到 1.3B 7-DOF latent-level，需要新增结构并重训**：至少包括 7-DOF joint action encoder/head、与视频 latent 的对齐训练、以及真正的 image-conditioned backbone。这些实验没有做，release 也没有打包相应权重。

release 中确实有一个 7-DOF latent-level 验证，但它是**小型 12.88M 3D U-Net**（`VideoWorldModel6D`），不是 Wan 1.3B。它证明“在 7 关节运动 latent 上做 every-step 硬投影”可行；不能外推成“Wan 1.3B 上也可行”。

## 8. 结论与边界

### 8.1 可以 claim 的

- 1.3B Control 可以稳定跟随 CNF 生成的 skeleton control；
- LoRA 在 1.3B 上仍有正收益（EPE `8.87 → 6.56 px`，PSNR `31.06 → 34.98 dB`）；
- **速度可靠时**，velocity-only 在像素和轨迹层面都一致优于 waypoint-only：干净数据 4/4 样本；含噪 waypoint + oracle 速度 8/8 关节 RMSE、7/8 PSNR；
- 速度约束在干净数据上的收益是**小而一致**的，不是数量级提升；
- PF_Wan 1.3B 的硬约束能显著降低 low-level objective，并泛化到 held-out clip；
- A14B oracle 中，CNF 和 soft 都能降低相对 roundtrip baseline 的轨迹误差。

### 8.2 不能 claim 的

- velocity-only 无条件优于 waypoint-only；
- 从含噪、低频 action 直接差分估计的速度足够可靠（4 px 噪声下反而比 waypoint-only 差）；
- 像素空间硬约束保证；
- 低 jerk 等于更自然；
- PF_Wan 1.3B 的低层目标改善已经转化为视频质量提升（当前没有）；
- A14B oracle 中 CNF 优于 soft（当前基本持平，cycle 更差）；
- 1.3B 上已经实现 7-DOF latent-level 硬约束（当前只有输入级 2D control 渲染和 release 的小型 7 关节 WM）。

### 8.3 失败判据（用于后续复现）

| 实验 | 失败判据 |
|---|---|
| A 干净数据 | LoRA 相对 base 没有稳定改善；velocity 不是 4/4 更好；EPE/PSNR 差异落在检测噪声内 |
| A 含噪数据 | oracle 速度不能改善 8/8 关节 RMSE 或 ≥7/8 PSNR；estimated 速度与 waypoint 无差异或更差 |
| B PF_Wan 1.3B | low-level objective 没有明显低于 soft；或视频动态 EPE 不低于 soft、动态位移仍接近静止（远小于参考 `80.89 px`） |
| C A14B oracle | CNF 动态 EPE 不优于 soft，或前后向一致性显著差于 soft/baseline |
| 7-DOF latent-level | 低层头仍只接受 `[B,K,T,2]`；没有接受 `[B,T,7]` 或 `[B,70]` 的 joint head；没有重训证据 |
